Swift Concurrency 学习笔记（附 Flutter / GCD 对照）

前言

本文从移动端跨端视角（Flutter + iOS）梳理 Swift 新并发模型，对比老方案 GCD、Flutter Isolate，方便复盘。

一、前置认知：async / await（基础基石）

  1. async：标记函数为可挂起函数，调用时必须写 await

  2. await：挂起当前异步任务，不阻塞线程

    • ✅ Swift Concurrency：线程释放回调度池，可以去跑别的任务；等异步结果回来，再恢复当前函数往下执行
    • ❌ GCD sync / 信号量阻塞：直接把线程卡死，线程不能干别的事

一句话区分：await 是暂停函数流程，不是卡住线程。

二、Task：结构化并发，任务树模型

Task 是开启异步任务的载体，分两种：

1. 普通 Task {}

  • 继承父任务的 Actor、优先级、取消信号
  • 属于结构化并发，依附父作用域（任务树的子节点）
  • 典型场景：SwiftUI .task 修饰符，视图销毁 → 自动取消这个 Task

2. Task.detached {} 分离任务

  • 脱离父任务上下文，是独立根任务，不受父任务、页面生命周期影响
  • 页面销毁不会自动取消，适合跨页面的长耗时任务（比如后台文件上传）
  • 只有任务代码执行完毕、内部主动 cancel、抛出未捕获异常才会结束

老方案对比：GCD 时代我们手动用数组存所有任务标识，页面退出遍历数组逐个 cancel，是扁平列表管理；Swift Concurrency 是树形结构，父取消自动递归通知全部子任务。

三、Actor：对象级并发安全（解决数据竞争）

  1. 定位：Swift 原生并发安全方案，和 class 平级的引用类型
  2. 核心规则：Actor 有自己独立的隔离域，外部访问它的方法/属性，必须 await
  3. 串行执行：所有进入 Actor 内部的调用排队执行，同一时刻只跑一段逻辑
  4. 和 atomic（OC）对比：
    • atomic：只保证单次读/写属性原子；复合操作（读→+1→写）依然竞争
    • Actor：整个对象内部逻辑串行隔离，复合操作天然安全，编译器强制校验，从编译期阻止非法跨线程访问
  5. 特殊 Actor：@MainActor，就是主线程隔离域，UI 状态更新放这里

跨端对照：和 Flutter Isolate 思想相似，都是隔离状态；区别是 Actor 可以互相 await 访问，Isolate 靠 port 发消息。

四、结构化取消（Cancellation）

  1. 绑定任务树：父任务取消，自动向下传递给所有子任务
  2. 取消不是“硬杀线程”：是在 await 挂起点检查取消标记，抛出 CancellationError，由业务捕获处理
  3. 优势：不用手动维护任务数组、不用逐个 cancel；作用域销毁自动清理
  4. 缺点：只有走到 await 点才会响应取消；纯 CPU 死循环、没有 await 的代码不会自动停下

五、AsyncSequence：异步数据流（持续源源不断的数据）

  1. 作用：处理持续推送的流式数据（定位更新、消息推送、文件变化、传感器数据）
  2. 写法：for await item in sequence { }
    • 没有新数据时，循环挂起、不占线程
    • 来了新数据，进入循环体处理
    • 外层 Task cancel，循环自动终止
  3. 老方案对比：传统 delegate / block 回调，需要手动持有 manager、手动停止监听、手动置空代理，样板代码多，容易内存泄漏

六、高频问答（精简版）

  1. await 会不会阻塞线程？
    不会，await 只挂起当前异步任务，线程放回调度池复用；GCD sync 才会阻塞线程。

  2. Task 和 Task.detached 的区别？什么时候用 detached？
    Task 依附父作用域，跟随父任务/视图生命周期自动取消；detached 是独立根任务，页面销毁不会停，适合跨页面后台上传。

  3. Actor 和 atomic 的区别？
    atomic 只保护单属性读写；Actor 是对象级隔离，保证一段复合逻辑串行执行，编译器强制安全检查。

  4. 什么是结构化取消？对比 GCD 手动 cancel？
    结构化取消基于任务树，父取消递归传给所有子任务；GCD 是扁平数组手动管理，容易漏 cancel。

  5. AsyncSequence 适合什么场景？怎么取消？
    持续流式异步数据；包在 Task 里，cancel Task 就停止 for await 循环。

七、整体小结

Swift Concurrency 整套体系目标：用 async/await 抹平回调地狱，用任务树 + Actor + 结构化取消，把并发安全、任务生命周期交给编译器和 runtime，替代过去大量依赖人工维护的 GCD、delegate 代码，写出更容易维护、不容易出数据竞争的异步代码。
